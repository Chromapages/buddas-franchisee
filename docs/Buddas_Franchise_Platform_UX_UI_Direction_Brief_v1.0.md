# Direct the Budda’s franchise platform UX and UI

**Document:** UX/UI direction brief  
**Product:** Budda’s franchise recruitment site and operator portal  
**Version:** 1.0  
**Date:** August 21, 2026  
**Status:** Proposed design direction  
**Primary audience:** Brand, product, design, accessibility, content, engineering, franchise development, and operations  
**Source documents:** Brand Strategy 01–10, Design System v2.0, Product Truth Master, Discovery Brief, Scope and Requirements, Sitemap and User Flows, Content Matrix  

This brief defines the brand inputs, visual references, mood, experience principles, accessibility standard, design-system needs, and responsive behavior for the public franchise site and protected operator portal.

## 1. Executive direction

The platform must feel:

> **Serious enough for diligence. Distinctive enough to remain Budda’s.**

The recommended direction is:

> **The Roll & Table: evidence you can taste.**

The Roll represents appetite, product ownership, movement, and the Budda Roll. The Table represents evidence, hospitality, operations, decisions, and shared responsibility.

The public franchise site should combine:

- Food strong enough to create craving
- Evidence structured enough to support diligence
- Story specific enough to protect Hawai‘i roots
- Calls to action clear enough to guide the next truthful commitment

The operator portal should combine:

- Location context
- Current information
- Task-first interaction
- Budda’s warmth without marketing theater
- High-density clarity without generic software styling

## 6. Visual system direction

### 6.1 Color

Locked palette:

| Role | Color | Hex |
| --- | --- | --- |
| Hospitality canvas | Budda’s Cream | `#FFF8E8` |
| Recognition | Base Teal | `#54BFA5` |
| Structure and action | Dark Teal | `#1C5F56` |
| Detail | Island Gold | `#E9C559` |
| Temporary signal | Sunset Orange | `#D36200` |
| Warm body ink | Cocoa | `#5A3A1F` |
| Utility | White | `#FFFFFF` |

Recommended overall ratio:

- 55–65% Cream and White
- 20–30% Base Teal and Dark Teal
- 5–10% Gold and Orange

Public franchise calibration:

- Increase Dark Teal for navigation, evidence rails, process, and final actions
- Use Base Teal for identity and active recognition
- Use Cocoa for body copy and bakery warmth
- Use Gold for metadata and small details
- Use Orange only for current, temporary, or urgent signals

Portal calibration:

- White and Cream working surfaces
- Dark Teal navigation and action
- Base Teal active state
- Functional status colors for success, warning, and error
- Minimal Gold and Orange

### 6.2 Contrast rules

Approved normal-text combinations:

- Dark Teal on Cream
- Cream or White on Dark Teal
- Cocoa on Cream
- Cocoa on White
- Cocoa on Base Teal

Do not use:

- White or Cream text on Base Teal for normal text
- Gold text on Cream
- White text on Orange for normal text
- Low-opacity borders as the only form boundary

### 6.3 Typography

Locked roles:

- Official Budda’s script: Brand artwork only
- Poppins: Display, hierarchy, labels, and strong actions
- DM Sans: Body, forms, tables, metadata, and portal utility

Recommended weights:

- Poppins: 400, 600, 700, 800
- DM Sans: 400, 500, 700

Direction:

- Restore the locked roles
- Remove Outfit unless Brand approves a documented exception
- Keep body copy at 16 CSS pixels or larger
- Use short, direct headings
- Use tabular numerals for data where supported
- Keep long reading columns between 55 and 75 characters

Content-fit limits:

| Element | Preferred | Review trigger |
| --- | ---: | ---: |
| Eyebrow | 2–6 words | More than 8 words |
| Hero headline | 2–8 words | More than 12 words |
| Hero support | 1–2 sentences | More than 220 characters |
| Primary CTA | 1–3 words | More than 18 characters |
| Section heading | 3–12 words | More than 16 words |
| Card title | 2–7 words | More than 10 words |
| Card body | 1–3 sentences | More than 280 characters |

If copy does not fit, revise the copy or component. Do not shrink type to preserve a desktop line break.

### 6.4 Grid

Locked grid:

- Desktop: 12 columns
- Tablet: 8 columns
- Mobile: 4 columns

Containers:

- Primary: 1,280 CSS pixels
- Editorial wide: 1,120 CSS pixels
- Reading: 720 CSS pixels
- Full bleed: Product and environment only

Gutters:

- Up to 479: 20 CSS pixels
- 480–767: 24 CSS pixels
- 768–1,023: 32 CSS pixels
- 1,024–1,279: 48 CSS pixels
- 1,280 and above: 64–96 CSS pixels

### 6.5 Shape and radius

Use:

- 8 CSS pixel controls
- 16 CSS pixel major containers
- Full radius for pills only
- Straight Table Lines
- Bold Roll Arc

Avoid:

- Every section inside a rounded card
- Nested rounded containers
- Decorative dots on line ends
- Thin arcs
- Rainbow or generic arches

### 6.6 Iconography

Icons should:

- Clarify function
- Use approved Utility Line geometry
- Sit inside a 44 CSS pixel target when interactive
- Include text labels when meaning is not universal
- Use Dark Teal by default
- Avoid decorative mixing with Product Markers

Portal status cannot rely on icon or color alone.

### 6.7 Photography

Public franchise mix:

- 40% Product Truth
- 25% Bakery Engine and process
- 20% Restaurant and hospitality
- 15% Origin, community, and operator context

Priority:

1. Budda Roll appetite
2. Real restaurant
3. Real process
4. Real people
5. Real support evidence

Avoid:

- Investor handshakes
- Laptop coffee meetings
- Generic smiling franchise owners
- Palm-tree establishing shots
- Composite stores presented as open
- Heavy overlays that mute food

### 6.8 Hero treatment

Desktop:

- Text 4–5 columns
- Food 7–8 columns
- Food may exceed container
- Localized gradient behind copy only
- Primary CTA and disclosure remain visible

Mobile:

- Product remains large
- Crop uses 4:5 or 9:16 art direction
- Copy stacks intentionally
- Haze does not cover the whole product
- CTA receives a full-width or near-full-width target
- Secondary proof follows the primary action

### 6.9 Motion

Motion grammar:

> Reveal → Land → Share

Use:

- One Arc reveal in a major appetite moment
- Table Line landing for structured evidence
- 160–280 ms functional transitions
- 360–520 ms image reveal
- 260–320 ms mobile navigation

Avoid:

- Bounce
- Rubber movement
- Infinite decorative motion
- Parallax that compromises reading
- Delayed controls
- Product stretching or floating
- Scroll choreography on every section

Reduced motion removes Arc sweeps, parallax, large translations, decorative loops, and scale choreography.

## 10. Accessibility standard

### 10.1 Target

**WCAG 2.2 AA**

Accessibility is a release requirement and part of the hospitality standard.

### 10.2 Color

- 4.5:1 for normal text
- 3:1 for qualifying large text
- 3:1 for meaningful component boundaries and graphics where required
- No color-only state
- Test forced colors

### 10.3 Focus and keyboard

- Use visible `:focus-visible` treatment
- Preferred 2–3 CSS pixel ring
- Maintain contrast across surfaces
- Do not clip or obscure focus
- Logical tab order
- Native controls before custom patterns
- Escape closes dismissible overlays
- Return focus after menu, modal, or drawer

WCAG 2.2 adds Focus Not Obscured at Level AA. Sticky actions, menus, banners, and chat surfaces must not hide the focused component. [W3C WCAG 2.2 changes](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/).

### 10.4 Targets

- Primary button: 48–56 CSS pixel height
- Standard input: 48–52 CSS pixel height
- Icon control: 44 by 44 CSS pixels preferred
- Navigation item: approximately 44 CSS pixel effective height
- WCAG 2.5.8 24 by 24 minimum and spacing exceptions remain the compliance floor

[W3C target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

### 10.5 Forms

- Visible label
- Programmatic label
- Required state
- Instructions before error
- Error linked to field
- Error summary
- Preserved input
- Correct keyboard type
- Autofill
- No validation on every keystroke
- Success and pending announcement

### 10.6 Authentication

- Accessible authentication under WCAG 2.2
- Allow password managers and paste
- Avoid cognitive-function tests
- Provide recovery
- Do not expose account existence
- Multi-factor flow receives assistive-technology testing

### 10.7 Tables and data

- Use semantic table only for true tabular relationships
- Provide caption and headers
- Preserve row identity on responsive transformation
- Do not hide material columns without another route
- Make sort state programmatic
- Provide text equivalent for charts

### 10.8 Motion

- Respect `prefers-reduced-motion`
- Do not animate essential status away
- No flashing
- No motion-trigger-only control
- No focus movement without user action

### 10.9 Zoom and reflow

- 200% text zoom
- 320 CSS pixel reflow
- No clipped text
- No fixed-height copy containers
- No horizontal scrolling for ordinary reading
- Keep actions reachable

### 10.10 Testing

Automated:

- axe or equivalent
- contrast
- semantic landmarks
- accessible names

Manual:

- Keyboard
- Desktop screen reader
- Mobile screen reader
- 200% zoom
- 320 CSS pixel reflow
- Forced colors
- Reduced motion
- Touch target review
- Error recovery

## 11. Responsive behavior

### 11.1 Breakpoint baseline

Breakpoints are content thresholds:

- `sm`: 480 CSS pixels
- `md`: 768 CSS pixels
- `lg`: 1,024 CSS pixels
- `xl`: 1,280 CSS pixels
- `2xl`: 1,536 CSS pixels

Use container queries when component width matters more than viewport width.

### 11.2 Responsive priority

At narrow widths preserve:

1. Comprehension
2. Product
3. Primary action
4. Brand recognition
5. Secondary information
6. Decoration

### 11.3 Header

Desktop:

- Logo left
- Five or fewer primary links
- Secondary login
- One primary inquiry action

Collapse navigation when content begins to crowd, not at a fixed device assumption. The current header needs an earlier collapse threshold before the login label and inquiry action collide.

Mobile:

- Logo
- Primary inquiry action
- Menu button
- Full-screen or large drawer
- Focus containment
- Escape and close action
- Body scroll control
- Same link order

### 11.4 Hero

Desktop:

```text
┌─────────────────────────────────────────────┐
│ LOGO / NAV                                  │
├───────────────────┬─────────────────────────┤
│ EYEBROW           │                         │
│ HEADLINE          │       REAL FOOD         │
│ SUPPORT           │       7–8 COLS          │
│ CTA               │                         │
│ PROOF             │                         │
└───────────────────┴─────────────────────────┘
```

Mobile:

```text
┌─────────────────────────┐
│ LOGO   CTA   MENU       │
├─────────────────────────┤
│ EYEBROW                 │
│ HEADLINE                │
│ SUPPORT                 │
│ PRIMARY CTA             │
│ DISCLOSURE              │
│ LARGE PRODUCT CROP      │
│ PROOF                   │
└─────────────────────────┘
```

The product may sit behind copy only when the gradient is localized and the food remains visible.

### 11.5 Numbered sections

Desktop:

- Number and label share a stable metadata row
- Sequence connects to actual order
- Table Line grounds the section

Mobile:

- Keep `01`, `02`, and later numbers on one line
- Use a two-column metadata grid for number and label
- Never let digits stack independently
- Convert horizontal timelines to vertical progression

### 11.6 Evidence ledger

Desktop:

- Two-column or three-column relationship
- Evidence rail aligns labels, source, and context
- Image may cross the rail once

Tablet:

- Eight-column split
- Collapse secondary metadata beneath evidence

Mobile:

- One-column rows
- Source and date remain visible
- No horizontal table for ordinary evidence

### 11.7 Forms

Desktop:

- Reading-width form
- One column by default
- Two columns only for tightly related short fields
- Summary or trust content adjacent but not competing

Mobile:

- One column
- Persistent labels
- Correct input modes
- Full-width primary action
- Sticky action only after testing
- Enough bottom clearance for safe area and keyboard

### 11.8 FAQ

Desktop:

- Reading-width accordion
- One expanded item by default only when useful

Mobile:

- Full-width rows
- 44 CSS pixel target or larger
- Heading and icon never collide
- Expanded content remains in document flow

### 11.9 Portal tables

Desktop:

- True tables for tabular orders and invoices
- Sticky column only when needed
- Horizontal scroll only inside the table region

Tablet:

- Reduce secondary columns
- Keep action, status, and identity

Mobile:

- Transform rows into labeled records
- Preserve row identity, status, total, and primary action
- Do not render tiny desktop tables

### 11.10 Portal navigation

Desktop:

- Persistent sidebar or top-level shell
- Location context visible

Tablet:

- Compact navigation
- Location switcher remains available

Mobile:

- Drawer or dedicated menu
- Current location in page header
- Cart and support remain reachable
- No competing bottom and top navigation

### 11.11 Photography

Produce sources and crops for:

- 21:9 safe
- 16:9
- 4:5
- 9:16

Use `next/image` `sizes` and art direction. Missing `sizes` can cause the browser to assume an image fills the viewport and download an unnecessarily large source. [Next.js Image guidance](https://nextjs.org/docs/app/api-reference/components/image).

### 11.12 Low bandwidth and interruption

- Show content before decorative motion
- Reserve layout space
- Preserve form state
- Load critical product image appropriately
- Lazy-load below-fold imagery
- Show stale or unavailable portal data explicitly
- Do not require an uninterrupted session for long forms

## 14. Performance and technical experience

Targets at the 75th percentile:

- Largest Contentful Paint: 2.5 seconds or less
- Interaction to Next Paint: 200 milliseconds or less
- Cumulative Layout Shift: 0.1 or less

Design requirements:

- Do not lazy-load the likely hero Largest Contentful Paint image
- Reserve media dimensions
- Do not send desktop-resolution sources to mobile
- Do not load desktop and mobile images simultaneously
- Do not hide headline or action behind animation

- Token namespaces have an approved source
- Generic card repetition is reduced
- Every page has one dominant visual idea

### UX

- Public pages guide evidence → fit → process → inquiry
- Portal pages keep location and state visible
- One primary action exists per stage
- Empty, stale, error, and success states are designed
- Booking, account, and checkout boundaries match the flow specification

### Accessibility

- WCAG 2.2 AA passes
- Keyboard and screen-reader journeys pass
- Focus remains visible and unobscured
- 200% zoom and 320 CSS pixel reflow pass
- Reduced motion preserves meaning
- Forms preserve values and announce errors

- 320, 375, 480, 768, 1,024, 1,280, 1,440, and 1,536 CSS pixel reviews pass
- Mobile art direction is intentional
- Section numbers do not split
- Navigation does not collide
- Tables transform without losing meaning
- Product remains visually dominant

- Core Web Vitals targets pass
- Media uses correct sources and sizes
- No layout shift from image or font loading
- Motion does not block interaction
