# Govern content across the Budda’s franchise platform

**Document:** Content matrix  
**Product:** Budda’s franchise recruitment site and operator portal  
**Version:** 1.0  
**Date:** August 21, 2026  
**Status:** Proposed content baseline  
**Primary audience:** Brand, franchise development, operations, legal, product, design, search, and engineering  
**Source documents:** Discovery Brief v1.0, Scope and Requirements v1.0, Sitemap and User Flows v1.0, Franchise Website PRD v1.0  

This matrix assigns each page a goal, audience, search topic, call to action, content owner, copy status, asset status, evidence requirement, and review cadence. It separates public search pages from protected operator tasks.

## 1. Executive summary

The public content system has one conversion objective:

> Help a qualified operator understand Budda’s, assess fit, and submit an informed inquiry.

The portal content system has one operational objective:

> Help an approved operator complete current, location-specific work without relying on stale documents or informal coordination.

The matrix uses four public content pillars:

1. Product and brand distinction
2. Operator fit and franchise readiness
3. Mutual-evaluation process
4. Operating support and evidence

Keyword targets in this document are directional hypotheses. Search-result language supports the topic families, but this work did not use a volume or difficulty dataset. Validate targets through Google Search Console, Google Ads Keyword Planner, Ahrefs, Semrush, or an approved equivalent before forecasting traffic.

## 2. Content status model

### 2.1 Copy statuses

| Status | Meaning |
| --- | --- |
| Published | Implemented in the current app |
| Published, review required | Implemented but needs owner, evidence, brand, or legal review |
| Revision required | Implemented but conflicts with approved scope or user flow |
| Draft required | Page exists but required content is missing |
| Demo-only | Copy supports a prototype and cannot ship as production operations |
| Conditional | Content is needed only after a release gate |
| Withdrawn | Must not render publicly |

### 2.2 Asset statuses

| Status | Meaning |
| --- | --- |
| Implemented | Asset exists and renders |
| Approval record required | Asset exists but rights, Product Truth, or brand approval is not recorded in this matrix |
| Refresh required | Asset is stale, inaccurate, low quality, or duplicates another page |
| Missing | Required asset does not exist |
| Demo-only | Asset or data is synthetic |
| Not required | Page works without a dedicated visual asset |

### 2.3 Evidence statuses

| Status | Meaning |
| --- | --- |
| Supported | Source exists and claim may remain with current context |
| Source review required | Source exists but period, geography, wording, or owner needs review |
| Legal review required | Claim touches franchise offer, investment, territory, performance, consent, or legal terms |
| Operational validation required | Copy describes a capability that operations must prove |
| Unsupported | Claim must be removed or withheld |

### 4.2 Keyword guardrails

- Do not target `franchise cost` with a page that withholds costs
- Do not target `profit`, `earnings`, `return`, `payback`, or `low-risk franchise` without approved Item 19 content and legal review
- Do not use `available territories` when the page collects market interest only
- Do not use `apply` when the action is an inquiry
- Do not use `authentic Hawaiian` as a blanket claim
- Do not repeat the primary keyword to meet a density target
- Use semantic entities and evidence instead of keyword stuffing

The Federal Trade Commission states that sales, income, or profit claims must appear in Item 19 and have a reasonable basis, subject to narrow exceptions. [FTC consumer guide](https://www.ftc.gov/business-guidance/resources/consumers-guide-buying-franchise).

## 12. Content production workflow

### 12.1 Workflow

1. Owner drafts against page goal and evidence
2. Brand reviews positioning, naming, Product Truth, and culture
3. Operations or finance verifies capability and facts
4. Legal reviews controlled claims and consent
5. Search reviews intent, metadata, internal links, and indexing
6. Accessibility review checks structure, alternatives, and readability
7. Content receives approved status and effective date
8. Engineering publishes the approved version
9. Analytics and owner monitor performance and staleness

## 13. Measurement plan

### Public content

Measure:

- Organic entrances by page and query
- Branded versus non-branded query
- Search click-through rate
- Evidence-section exposure
- CTA click
- Inquiry start
- Durable inquiry
- Qualified inquiry
- Lead-to-conversation

Do not judge content only by traffic. A lower-volume page can be valuable if it improves qualified decisions or prevents inappropriate inquiries.

### Portal content

Measure:

- Task completion
- Resource findability
- Stale-resource incidents
- Support deflection when appropriate
- Order error
- Time to complete
- Accessibility failure

Portal search traffic is irrelevant because protected pages remain noindex.

## 14. Acceptance criteria

### Matrix completion

- Every canonical page has one goal
- Every public page has one primary topic
- Every page has one primary CTA or an explicit no-CTA decision
- Every page has one accountable owner
- Copy and asset status use the defined vocabulary
- Every regulated claim names a required reviewer
- Every asset identifies a source or missing source record

### Public content

- Metadata matches visible content
- Keyword language reads naturally
- No page targets a promise it cannot answer
- No unsupported superlative appears
- No active-offer implication appears in Release 1
- Internal links support the defined journey
- Copy works at 320 CSS pixels and 200% zoom

### Portal content

- Protected pages are noindex
- Labels name the real operator task
- Data includes source and freshness when needed
- Empty, stale, error, and unavailable states exist
- Demo copy cannot appear in production
- Location context remains visible during consequential tasks
