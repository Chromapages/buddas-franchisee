# Mobile Operator Workspace style rollout

## Plan

1. Load a shared mobile stylesheet from the authenticated Portal layout. Reuse the existing brand variables, header, panel, button, and state components; add no runtime dependencies.
2. Apply Dashboard typography and spacing to page stacks: 20px gutters, 28px section rhythm, 16px panel padding, 14–16px radii, Poppins headings and DM Sans body text. Keep the desktop breakpoint at 77.8125rem.
3. Adapt Supplies cards and controls; Orders/Support filters, lists, and details; Cart/Checkout costs and forms; Resource/Bulletin records; Account sections and Growth forms. Retain canonical identifiers, status labels, targeting and server actions.
4. Give interactive controls comfortable 48px minimum height, 16px editable input text, wrapping toolbars, and visible inherited focus. Do not introduce fixed action bars over the bottom navigation.
5. Inspect the resulting pages at compact widths and enlarged text. Record evidence and limitations rather than claiming full backend or device certification.

## Acceptance

- Only authenticated Portal mobile styles change; desktop and marketing are outside the media-scoped selectors.
- Each page has a compact title and consistent section rhythm without adding card wrappers to the entire page.
- Forms and narrow lists stack naturally; identifiers and summaries wrap; meaningful status colors remain intact.
- Existing data, errors, permissions, navigation and confirmations continue to use their original components.

## Verification and risks

Use local rendered pages when authenticated fixtures are available. Check 320px and 430px plus 200% text enlargement. A 1280px comparison must show no application of the new stylesheet's rules. Shared selector changes need visual review of active records as well as empty states. Production Firebase/account workflows are not simulated by visual fixtures. The existing repository has unrelated test and type failures; this rollout does not resolve those.

## Delivered

Shared rules live in `src/app/portal/operator-mobile.css`, imported once by the authenticated layout. The reusable CSS hooks are `mobile-workspace-panel`, `mobile-workspace-toolbar`, `mobile-workspace-list`, and `mobile-workspace-record-header`; existing domain class names use the same tokens. No duplicate React wrappers or client JavaScript were introduced for styling.

Catalog, Orders, Support, Resources and Bulletins received explicit hooks. Cart/Checkout, Account and Growth reuse their existing semantic class names. Controls use 48px minimum height and editable fields use 16px text. Gutters/panel padding remain 20px/16px when text enlarges, preserving usable reading width. Catalog primary actions use dark teal; semantic Added state remains distinct. Order amounts can move to a new row without being squeezed into a narrow column.

Visual evidence: `design-qa/mobile-workspace-styles/`, generated by `scripts/mobile-workspace-style-check.py` using the existing Python Playwright installation. Forty render cases cover ten page/form states at 320px, 430px, 320px with doubled root font size, and 1280px desktop. The isolated seed server has external storage disabled. Account and Growth cover their available local data/error presentation, not live financial or provisioning workflows. The 195px effective viewport and physical-device screen readers are outside this pass.

The first pass found 27px cart overflow at doubled text size. Fixed by keeping mobile gutters/padding constant and reducing the quantity input's width while preserving its text size. Subsequent render checks reported HTTP 200 and zero horizontal overflow in all 40 cases. No orders, tickets, acknowledgements, or account mutations were submitted.
